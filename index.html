Understand PipeFuzz

PipeFuzz tests your PySpark transformations with small, deliberately awkward datasets. You describe the input schema and the rules that should hold. It generates records, runs real Spark, and reduces failures to a case you can investigate.

Run your first testExplore the join example
v0.1 is focused, by design. Python functions in, PySpark DataFrames out. Local execution. Explicit checks. No production data required.

Why use PipeFuzz?

A pipeline can pass a test with clean sample data and still fail when a dimension contains duplicates or a column contains NULL. Instead of writing one expected output for one hand-picked input, you tell PipeFuzz a property that should remain true across generated inputs.

For example: “Joining orders to customers must not increase the total order amount.” PipeFuzz supplies matching keys and duplicate customer records to challenge that assumption.

Four steps to a useful failure

01 / DEFINEDescribe a contract

Input types, relationships, and the invariants you expect.

02 / GENERATEChallenge the inputs

Hypothesis builds small, schema-valid adversarial records.

03 / EXECUTERun real Spark

Your transformation runs against local DataFrames.

04 / REDUCEInspect a small case

Failures are shrunk and reported with a reproduction seed.

An invariant is the rule being checked. A scenario is the kind of input used to challenge it. For example, join_amplification generates duplicate dimension keys; no_join_amplification checks that the configured measure does not increase.

What does a passing run mean?

It means the sampled generated inputs did not violate your configured invariants. It does not prove that every input is safe, that the business rules are complete, or that a stateful pipeline is idempotent.

Use PipeFuzz alongside ordinary unit tests, known business examples, and integration tests. It adds adversarial coverage; it does not replace them.

Project status

PipeFuzz 0.1.0 is an alpha package, installed from a source checkout. There is no claimed PyPI release. The repository includes real-Spark tests and an adversarial release audit; see verification and limitations before relying on broader compatibility claims.
