Your first PipeFuzz run

Run a real PySpark transformation against small generated inputs, then use the first failure to understand the violated property. The bundled join examples take you from an inflated measure to a passing check.

Requirements

Use Python 3.10–3.13 and Java 17 or later, with Java available to your shell. PipeFuzz 0.1.0 declares these Python versions in its package metadata. The recorded release audit executed Windows with Python 3.13 and Java 17; the other declared Python versions and macOS/Linux were not executed in that audit.

Installation is from a repository checkout. A PyPI release is not claimed. Git is needed only if you clone the repository.

Get the code

git clone https://github.com/Jagadeeswaran-DE/pipefuzz.git
cd pipefuzz
The package source is currently private. This documentation is public, but cloning the package requires access to Jagadeeswaran-DE/pipefuzz and an authenticated Git client. A GitHub 404 can mean your account does not have access. You can also use an existing authorized checkout. Run the commands below from its root directory.

Install in a virtual environment

These commands use the virtual environment's executables directly, so shell activation is optional. Check that the selected Python interpreter is within the supported range before creating the environment.

Windows · PowerShell

python --version
java -version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\pipefuzz.exe --version

macOS / Linux · POSIX shell

python3 --version
java -version
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/pipefuzz --version

The version command prints PipeFuzz 0.1.0 for this checkout. If Java is unavailable, install a compatible JDK and configure JAVA_HOME and PATH before running a transformation. For an editable development install, replace pip install . with pip install -e ".[dev]".

Find the broken join

The first example joins orders to customers and sums each country's order amounts. A duplicated customer key makes the same order contribute more than once. The configuration asks PipeFuzz to generate that structure and checks the resulting measure.

Windows · PowerShell

.\.venv\Scripts\pipefuzz.exe test examples/broken_join/pipeline.py::transform --config examples/broken_join/pipefuzz.yaml --max-examples 1 --seed 20260820
$LASTEXITCODE

macOS / Linux · POSIX shell

.venv/bin/pipefuzz test examples/broken_join/pipeline.py::transform --config examples/broken_join/pipefuzz.yaml --max-examples 1 --seed 20260820
echo $?

The intended result is INVARIANT_VIOLATION with exit code 1. That is the demonstration succeeding: PipeFuzz found a violation of no_join_amplification. The report includes the failing scenario, minimized input records and schemas, the reason, and a reproduction command. The recorded audit case shows one order's amount increasing from 1.0 to 2.0.

--max-examples 1 limits the initial Hypothesis exploration for each scenario. Failure reproduction and shrinking can execute additional examples, so the report may show a larger count.

Try the protected join

Run the companion example, which deduplicates customer keys before joining.

Windows · PowerShell

.\.venv\Scripts\pipefuzz.exe test examples/safe_join/pipeline.py::transform --config examples/safe_join/pipefuzz.yaml --max-examples 1 --seed 20260820
$LASTEXITCODE

macOS / Linux · POSIX shell

.venv/bin/pipefuzz test examples/safe_join/pipeline.py::transform --config examples/safe_join/pipefuzz.yaml --max-examples 1 --seed 20260820
echo $?

The recorded audit returned PASSED and exit code 0. A passing run means the generated cases did not violate the configured invariant; it does not establish correctness for every possible input. Read the deduplication caveat before using this pattern with conflicting dimension records.

Test your transformation

  1. Expose a Python callable that accepts keyword arguments matching the configured input names and returns one PySpark DataFrame.
  2. Define input schemas, row bounds, any relationships, scenarios, and explicit invariants in pipefuzz.yaml.
  3. Run pipefuzz test path/to/pipeline.py::transform using your environment's CLI. With no --config, a file target uses pipefuzz.yaml beside that file.

Start with the configuration reference and select checks that match your transformation's semantics. PipeFuzz runs locally and collects generated outputs to the driver, so keep transformations and generated results small. The architecture guide explains the execution boundary.
